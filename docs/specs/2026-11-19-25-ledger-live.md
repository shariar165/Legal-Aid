## Done
### 3. `AIN_LEDGER`
- `config.ledger_enabled()`: `AIN_LEDGER` of `1` or `0` (surrounding spaces ignored) wins; empty or unset falls back
  to `config.yaml`; any other value raises `ConfigError`, and the API checks it at startup, so a typo on a deployment
  stops the start instead of quietly leaving the feature off.
- `/api/health` reports `four_ledgers: true|false`, so a deployment's state can be read without logging in.
- `tests/conftest.py` drops `AIN_LEDGER` from the environment, so the suite always starts from `config.yaml`.
- Tests (`tests/test_ledger_env.py`): unset/empty use the file; `1` and `0` override it both ways; `true`, `on`,
  `yes`, `2` are refused, also at startup; end to end through the environment only, `AIN_LEDGER=1` gives ledgers,
  the demo promises, PB-PROMISE-GAP and PB-HOURS on the Malaysian text sample, and `AIN_LEDGER=0` removes them even
  when the file says on.
- `pytest` offline: 368 passed (also with `AIN_LEDGER=1` set in the shell).

### 4. Fake gold set, flag on vs off
Five gold documents, fake LLM, no promises (the gold run passes none), `AIN_LEDGER=0` then `1`:

| Document | Off | On | Difference |
|---|---|---|---|
| migrant_my_contract | 9 risks, recall 1.0, precision 1.0, 82 calls | 10 risks, recall 1.0, precision 0.9, 89 calls | **+ PB-HOURS** |
| migrant_sa_contract | 9, 0.9, 1.0, 82 | same | none |
| rmg_dhaka_epz | 12, 1.0, 1.0, 65 | same | none |
| long_migrant_msa | 11, 1.0, 1.0, 111 | same | none |
| control_clean | 0, –, 1.0, 3 | same | none |

No risk is lost. The one added risk is PB-HOURS on the Malaysian contract's clause C6 (12 normal hours a day against
the 8 of Employment Act 1955 s.60A), high, verified on `MY-EA-1955-s60A`. It is correct; precision falls to 0.9 only
because `gold.yaml` has no hours expectation (the gold set predates PB-HOURS and is scored with the flag off). The
seven extra calls are that risk going through the gates (one entailment call) and the bench (three opinions, three
reviews, the chair: the drafter's memo call is the same count with a different prompt). Citation validity stays 1.0
everywhere. PB-PROMISE-GAP needs what the worker was told, so it appears only with promises (with the demo promises
on the Malaysian text sample it is added too, verified on OEMA 2013 s.31(ঘ)).

Prompt hashes, fake mode, every LLM call: flag off is identical to the desk-review run. Flag on changes the
**Adversary prompt on three documents**, because it lists every active rule: PB-HOURS and PB-PROMISE-GAP on the
Malaysian contract, PB-PROMISE-GAP (pack `bd_migration`) on the Saudi contract and on the long MSA (10 map calls and
the reduce). The fake Adversary answers the same whatever the prompt, so the fake gold set cannot show what a live
Adversary does with the longer rule list; the live run (step 5) and the re-warm must cover the Saudi and long-MSA
samples too, not only the Malaysian one. EPZ and the control document are unchanged.
