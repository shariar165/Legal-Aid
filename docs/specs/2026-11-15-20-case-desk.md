# Spec 20: Case Desk, a UI upgrade in three phases

Approved in plan mode on 2026-11-15. Branch `case-desk` off `four-ledgers` (clean at fc0938f).
It does not depend on `rehearsal`. I stop for your approval after this plan and after each phase. One commit per phase.

## Context
- Citizen and Counsel look like two products. Citizen uses a warm beige ground with Hind Siliguri only. Counsel uses a
  cool grey with Inter and Source Serif. There are three token lists: `globals.css :root`, `counsel.module.css .page`
  and `docs.module.css .page`. Docs is out of scope and stays as it is.
- Neither mode leads with money. Counsel's wage card sits second, and Citizen opens with a danger banner.
- Counsel spreads one risk's evidence across Report, Contract, Council and Checks, and most of its text is 11.5–15px.
- Four Ledgers (spec 19) has no frontend yet. `AnalysisResult.four_ledgers` holds rows, `claim_projection`,
  `promise_gap`, `break_even` and `pending_risks`. `POST /api/jobs/{id}/promises` and `/promises/verify` exist and
  answer 404 while `ledger.enabled` is off.
- Reference: `docs/design/case-desk-reference.html` (read in full) and `desk.png` (checked; it is the same page
  rendered at about 1440px). See "Reference check" below.

## Decisions taken (from your answers and the code)
1. **Bangla cells are formatted in the frontend.** Cells are rebuilt from structured fields (term, amount, currency,
   party, months) with `STRINGS` and `formatNumber`. Text that cannot be rebuilt, such as the stepped deduction note,
   stays in the backend's English. There is no backend change, so pytest stays as it is.
2. **Rows.** With `four_ledgers` present: its rows first, then one "risk row" for each live risk that no ledger row
   links to. The reference's "অভিযোগের অধিকার" row is this kind. With the flag off or an old result, there are risk rows
   only: said and paid empty, paper = the clause, law = the verified citations.
3. **Law cells show the verified citation** (`citeLabel` of the section in the citation ledger) and its status, never
   a hand-written summary of the law. "ভঙ্গ / Breach" shows only on a backend `paper_vs_law` mismatch.
4. **Arithmetic in the frontend.** Bar widths are proportions. Each hero delta chip is a backend number: said→paper
   is `promise_gap.monthly`, and paper→take-home is `wage.monthly_deductions`. The headline loss is the sum of those
   two backend figures. This is display arithmetic, with no law in it. If the said currency differs from the wage
   currency, the said bar shows its value but is not scaled, and gets no delta chip.
5. **Add what was said, Verify and the citizen step appear only when `four_ledgers` exists.** They post, then refetch
   the whole result (new `reload()` in `useAnalysis`), so risks, the citation ledger and stats stay consistent. With the
   flag off there is a muted note instead. Citizen answers are merged into any existing `promises` before posting, so
   demo fields like hours and the exchange rate are not wiped.
6. **Pending promise risks** (`pending_risks`, `risk_status: "not_verified_yet"`) show "এখনো যাচাই হয়নি / Not verified
   yet" and a Verify button in Counsel. "Ask the council" stays disabled for them, because the council needs the risk
   in `result.risks`. Citizen shows the status line but no Verify button, since verifying makes model calls.
7. **Left pane when stacked.** DOM order stays contract → rows → evidence, so focus order matches the desktop.
   Under 1100px the contract pane collapses into a closed disclosure, and selecting a row scrolls the evidence file
   into view.
8. **Frontend tests.** The repo has no frontend test runner. Row-building lives in a pure `lib/desk/rows.ts` and is
   verified in the browser. Say so if you want a `node:test` harness added; that would be extra scope.

## Backend round before Phase 1 (2026-11-15, asked after Phase 0)
The Case Desk shows these values, so they are fixed in the backend first. Tests come first; the report comes before
the commit.

1. **Bilingual cells.**
   - `LedgerCell.value`, `BreakEven.note` and the claim-line and term labels become `L10n`.
   - A saved string from an older result loads as the English text, with the same text in `bn`.
   - `LedgerCell.party` is added. Bangla cell text uses Bangla digits for counts, as the reference does; money stays
     `RM 1,200`.
   - `Mismatch.detail.bn` is written per term as a natural sentence, not "Told … the contract says …" with English
     inside it.
   - A test checks that no `bn` string holds a Latin word other than a currency code.
   - This supersedes decision 1 above: the frontend shows these strings and does not rebuild them.
2. **The four regex facts**, worked out per clause and per sentence. Each returns its clause id in
   `DocFacts.fact_clauses`, and gives `None` when two readings disagree.
   - **Contract term:** a probation, notice, trial or leave period is skipped, and so is a period that follows "and" or
     is followed by "afterwards".
   - **Hours:** a figure next to overtime, "not exceed", maximum, "reduced to" or Ramadan is skipped.
   - **Passport:** read sentence by sentence. "Custody" counts only when it is the employer's, company's or agency's.
     "Worker shall keep or retain" and "remain in the Worker's own custody" mean the worker holds it.
   - **Ticket:** a return ticket is skipped, and a worker/employer conflict gives `None`.
   - The ledger takes the paper cell's clause from `fact_clauses`.
   - These facts reach no prompt, so the cache keys do not change.
3. **Contract term confirmation**, the same idea as the OCR salary check, with no model call:
   - `POST /api/jobs/{id}/term {months}` (404 with the flag off, 409 while the job runs, 422 outside 1–240) sets
     `facts.contract_months` and `contract_months_confirmed`, then rebuilds the Four Ledgers.
   - `ClaimProjection.term` = `{months, source: user | contract | worker, clause_id, label}`.
   - The labels are "term confirmed by user", "term read from the contract" and "term the worker was told (none on
     paper)".
4. **Law cell for the UI.**
   - `LawCell.title` is a short title per rule, such as "Minimum wage". For PB-PROMISE-GAP it reads "may fall under
     the cited section", never a proven offence.
   - A `paper_vs_law` mismatch carries `risk_status`.
   - `AnalysisResult.citation_names` (a computed field built with `naming.label`) gives every cited section's name in
     bn and en, so older results get it too.
5. **Fonts.** Inter and Source Serif 4 preload 99,384 bytes on `/` (48,432 + 50,952; measured from the build's
   preload headers). That is not over ~100 KB, so they stay at the root.
6. **README.** The "Honest limitations" section gets lines on the regex facts.

Verification: the new tests, then the full `pytest`, then `eval.run_eval` in fake mode to show the gold set holds. No
prompt changes.

## Phase 1 corrections (2026-11-15; the reference was drawn before the backend existed)
- **Headline.** Nothing has been paid yet, so nothing is "lost". It says take-home on paper is RM X a month less than
  the worker was told, where X = told minus take-home on paper (`said.amount − wage.net`, same currency only). This
  replaces decision 4's sum of the two chips.
- **Chain nodes.**
  - ≠ only where a Mismatch of that type exists.
  - = only when both cells exist, are comparable and have no mismatch.
  - Otherwise a neutral dash.
  - Recruitment cost "already paid" is a fact, not a promise, so it never gets ≠ or =.
  - Paper↔paid is always a dash.
- **Law cell badge.**
  - "violation" only for a `paper_vs_law` mismatch whose `risk_status` is verified.
  - "partial", "not verified" and "not verified yet" each get their own label.
  - A verified law with no violation reads "ধারা যাচাইকৃত" / "section verified". The gates verify the cited section,
    not that anyone broke it; next to "may fall under", the bare word "verified" would read as a proven offence.
  - The promise gap shows its backend title ("may fall under the cited section…"), never a proven offence.
- **Law cell text.** `LawCell.title` / `Mismatch.title` and the citation's name from `citation_names` in the UI
  language. The verbatim quote is shown only in the evidence file.
- **Contract term.** The term and its confirm/correct control (`POST /term`) sit next to the projection.
- **Header.** The dark green header is shared by every Counsel view, so the views keep one shell.
